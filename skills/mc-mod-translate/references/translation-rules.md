# 模组汉化细则

本文件是 `mc-mod-translate` 模式的完整翻译规范。`SKILL.md` 里的速查表不够用时读这里。

---

## 1. 保留项清单

下面这些东西**一个字节都不能动**，`check` 会把差异报成 `format` 错误：

| 类别 | 例子 | 说明 |
|---|---|---|
| Java 格式化符 | `%s` `%d` `%f` `%1$s` `%2$.2f` `%05d` `%%` | 数量和转换类型必须一致 |
| 花括号占位符 | `{0}` `{player}` `{count}` | 部分模组用 MessageFormat |
| 段落格式码 | `§6` `§l` `§r` `§#RRGGBB`（部分模组扩展） | 顺序也要一致 |
| 转义序列 | `\n` `\t` `\"` | 数量一致，不能引入新行 |
| HTML / 富文本 | `<br>` `<color=red>` | 成对保留 |
| 前后空格 | `" Stored"` / `"Stored "` | 影响 GUI 对齐 |
| 空串 | `""` | 保持空串，不要补内容 |

### 占位符换位的红线

- 原文是 `%s ... %s`（无序号）：**保持参数顺序**。改成 `%1$s` 会覆盖参数位置语义，等于改行为。
- 原文是 `%1$s ... %2$s`：可以自由换位，但必须整串都用带序号形式，不能混用 `%s` 和 `%1$s`（Java 会抛异常）。

## 2. 按 key 分类的处理

key 的命名基本能看出条目性质：

| key 形态 | 性质 | 处理 |
|---|---|---|
| `item.<mod>.*` / `block.<mod>.*` | 物品/方块名 | 名词短语，无标点，不加量词 |
| `itemGroup.<mod>.*` | 创造模式物品栏名 | 简短；模组品牌名可保留原文 |
| `entity.<mod>.*` | 生物名 | 名词，不带「的」 |
| `effect.<mod>.*` | 状态效果 | 名词短语，如「缓降」 |
| `enchantment.<mod>.*` | 附魔 | 名词短语 |
| `tooltip.<mod>.*` / `*.tooltip` | 悬浮提示 | 可多行，保留 `\n` |
| `gui.<mod>.*` / `*.button` | 界面文字 | 极简，不加句号，宁短勿长 |
| `message.<mod>.*` / `*.chat` | 聊天/系统消息 | 完整句，全角标点 |
| `advancements.<mod>.*.title` | 进度标题 | 短语，通常 2–6 字 |
| `advancements.<mod>.*.description` | 进度描述 | 完整句 |
| `subtitles.<mod>.*` | 音效字幕 | `<主体>：<动作>`，全角冒号 |
| `config.<mod>.*` / `*.option` | 配置项 | 直译，尽量短 |
| `death.<mod>.*` | 死亡消息 | 「%s 死于 %s」类句式 |
| `jei.<mod>.*` / `*.category` | 配方分类 | 名词短语 |
| `patchouli.*` / `book.*` | 手册正文 | 按散文翻译，保留 `$(...)` 宏 |

## 3. 中文书写规范

### 标点
- 正文用全角：`，。：；！？（）【】“”‘’`。
- 物品名、按钮、标签**不加句号**。
- 原文以 `...` 结尾时用 `…`；原文是 `:` 结尾时用 `：`。
- 原文没有的标点不要自行添加；原文有的标点不要删除。

### 空格
- 中文与拉丁字母/阿拉伯数字之间加一个半角空格：`已储存 64 FE`、`使用 Create 扳手`。
- 中文与中文之间不加空格。
- 数字后接中文单位不加空格：`3 个` → 数字与「个」之间有空格（因为「个」是中文单位，习惯上 `3 个` 有空格）。统一规则：**数字与中文之间加空格**。

### 通顺度

格式全对不等于读着顺。中文的语序、定语长度、指代习惯和外语句式差得远，直译过来的长句往往"每个字都对，连起来不像人话"。

校对时逐条问自己：

1. **一句话里几个「的」？** 超过两个就考虑拆句或换句式。
2. **主语还在吗？** 长句里「它」指代超过一个对象时，换成具体名词。
3. **定语是不是太长？** 中文习惯「短定语 + 主谓」，英语/俄语习惯「从句后置」，照搬会变成「被 X 的 Y 的 Z」。
4. **动词被名词化了吗？** 「进行组装」→「组装」，「做出调整」→「调整」。
5. **有没有空转的尾巴？** 「……的一切」「……的情况」「……方面」大多是翻译腔，删掉不影响信息。
6. **搭配对不对？** 「最费应力」「走过天花板」这种，中文里没人这么说。

改完必须重跑 `check`——语序调了，占位符和 `_下划线_` 很容易跟着跑位。**只调语序和用词，不增不减信息。**

### 数字与单位
- 单位（`FE`、`RF`、`mB`、`t`、`s`、`hp`）不译，保留原样。
- 不要做单位换算，不要改数值。
- 千分位、小数点在英文里是 `1,000` / `1.5`，中文保持原样。

### 专有名词
- 模组自造名词（如 `Andesite Alloy`、`Kinetic Mechanism`）先查术语库，再查作者官方中文，最后按字面直译并在 `glossary.json` 固化。
- 同一概念在全文件、全项目内必须同一译法。
- 品牌名（`Create`、`Botania`、`Applied Energistics`）默认不译；若社区已有约定译名（如 `Mekanism` → `通用机械`），用约定名并记进术语表。

## 4. 术语决策流程

1. `glossary lookup "<英文>"` —— 看整串记忆与术语拆解。
2. `glossary search <关键词>` —— 模糊查，找同类词的既有译法。
3. `glossary qa --key <key> --en "<英文>"` —— 看 CFPA 对这类结构的硬性要求。
4. 仍无结果时，检索作者仓库 / 官方 Wiki / MC 百科，确认社区通行的中文名。
5. 涉及现实行业术语（过山车、铁路、航空、医学等）时，**查中文行业文献、专利、厂商资料**，不要只按字面翻。
6. **仍有疑问就停下来给选项**，写清依据、优点、缺点，标出推荐项，由用户决定。
7. **写术语表前先确认**：把「操作 / 条目 / 位置 / 理由 / 影响」列成清单给用户，经确认后再落盘。

`glossary.json` 的 `terms` 是**强制**的：`check` 会对包含该英文词的条目校验译文里是否出现指定中文，并报告同一术语的多译法。

## 5. CFPA 官方 QA 规则摘要

来自 `CFPAOrg/Glossary` 的 `Vanilla/terms/qa-rules.tsv`，模组里出现同类结构时同样适用：

| 结构 | 要求 |
|---|---|
| `Deepslate` + (≤3 词) + `Ore` | 译「深层」：`Deepslate Iron Ore` → `深层铁矿石` |
| `Deepslate` 修饰非矿石 | 译「深板岩」：`Deepslate Bricks` → `深板岩砖` |
| `Wall <block>`（`wall_*` 类 key） | 译「墙上的」：`Wall Sign` → `墙上的告示牌` |
| `Exposed ... Copper`（非涂蜡） | 译「斑驳的」 |
| `Weathered ... Copper`（非涂蜡） | 译「锈蚀的」 |
| `Oxidized ... Copper`（非涂蜡） | 译「氧化的」 |
| `Waxed ... Copper` | 译「涂蜡」，「的」可有可无 |
| `Raw Iron/Gold/Copper` | 译「粗」：`Raw Iron` → `粗铁` |
| `Dead <Coral>` | 译「失活」 |
| `Suspicious <block>` | 译「可疑的」；`Suspicious Stew` 例外，译「谜之炖菜」 |

## 6. 正/反例对照

| 原文 | 好 | 差 | 原因 |
|---|---|---|---|
| `Iron Gear` | 铁齿轮 | 铁制的齿轮 / 铁 齿轮 | 多余的「的」、多余空格 |
| `Stored: %d%%` | 已储存：%d%% | 储存 %d%% 完成 | 丢失冒号语义、擅改标点 |
| `%s was slain by %s using %s` | %s 被 %s 用 %s 杀死了 | %s 被 %s 使用 %s 击杀 | 前者顺序正确；后者把 `using %s` 和 `by %s` 位置调换则非法 |
| `Block broken` | 方块：被破坏 | 方块被破坏了 | 字幕要「主体：动作」，且不带「了」 |
| `Machine hums` | 机器：嗡嗡作响 | 机器嗡嗡叫 | 字幕句式不完整 |
| `Energy Cell` | 能量单元 | 能量电池 | 术语不统一（同文件里另一个 `Battery` 才是电池） |
| `Getting Started`（进度标题） | 入门 | 开始游戏吧 | 进度标题要短语 |
| `Deepslate Iron Ore` | 深层铁矿石 | 深板岩铁矿石 | 与官方译法不一致 |
| `Suspicious Stew` | 谜之炖菜 | 可疑的炖菜 | 官方特例 |
| `Test Mod`（itemGroup） | Test Mod | 测试模组 | 品牌名进 `do_not_translate` |

## 7. 加载器与版本差异

- **Fabric**：`fabric.mod.json` 的 `depends.minecraft` 是版本约束字符串，可直接读。
- **Forge/NeoForge**：`META-INF/mods.toml` / `META-INF/neoforge.mods.toml`，`[[mods]]` 下取 `modId`，`[[dependencies.<id>]]` 里找 `modId="minecraft"` 的 `versionRange`。
- **1.7.10 / 1.12.2 老模组**：语言文件可能是 `lang/en_US.lang`（`.lang` 格式，`key=value`）。本工具只处理 JSON；遇到 `.lang` 需先转成 JSON 或手工处理，并在汇报里说明。
- **嵌套 jar**（Fabric JiJ、Forge JarJar）：工具会自动穿进 `META-INF/jars/*.jar`，译文会写回内层 jar。
- **MCreator 生成的模组**：jar 里有 `net/mcreator/` 包（`probe` 会显示 `generator=MCreator`）。这类模组的语言文件是导出器随手写的，**键序完全随机**，`extract` 会自动按键名排序后再生成骨架；排序后 `block.*`、`item.*`、`gui.*` 等前缀各自聚成一段，审查和分批翻译都不用自己对齐。确实要保留乱序时加 `--no-sort`，其他模组想跟着排序加 `--sort`。
- **已是中文的模组**：jar 内若已有 `zh_cn.json`，`extract` 会自动沿用，只翻缺失部分。

## 8. 交付产物

**唯一交付物是资源包**，原 jar 不改动、不重打包。

```
out/<jar名>-zh_cn-resourcepack.zip
├─ pack.mcmeta                                    {"pack":{"pack_format":N,"description":"..."}}
└─ assets/<命名空间>/lang/zh_cn.json              每个源语言文件一份
```

使用方式：把 zip 放进 `.minecraft/resourcepacks/`，游戏内「选项 → 资源包」启用即可。
资源包按命名空间覆盖，所以只影响目标模组，不会波及其他模组。

**产物留在工作目录的 `out/` 下即可，不要额外拷贝到桌面、`resourcepacks/` 或其他位置**，汇报里给绝对路径就够。

`pack_format` 由模组的 Minecraft 版本自动推断（`--pack-format N` 可覆盖）：

| MC | pack_format | MC | pack_format |
|---|---|---|---|
| 1.13–1.14.4 | 4 | 1.20.2 | 18 |
| 1.15–1.16.1 | 5 | 1.20.3–1.20.4 | 22 |
| 1.16.2–1.16.5 | 6 | 1.20.5–1.20.6 | 32 |
| 1.17 | 7 | 1.21–1.21.1 | 34 |
| 1.18 | 8 | 1.21.2–1.21.3 | 42 |
| 1.19–1.19.2 | 9 | 1.21.4 | 46 |
| 1.19.3 | 12 | 1.21.5 | 55 |
| 1.19.4 | 13 | 1.21.6–1.21.8 | 64 |
| 1.20–1.20.1 | 15 | | |

注意：

- 资源包对模组界面文字（GUI、tooltip、物品名）全部生效；少数模组把文本硬编码在代码里，资源包覆盖不到，这类条目要在汇报里单独说明。
- 整合包分发时，资源包可以直接打进整合包的 `resourcepacks/` 并在 `options.txt` 里启用。
- 如果用户**明确要求**覆盖原 jar，才加 `--jar` 生成 `out/<jar名>-zh_cn.jar`；这一步会破坏 jar 签名（若有），且用户后续更新模组时会被覆盖。

## 9. 术语库的更新

术语库数据在 `<Base directory>/glossary/`：

```
glossary/raw/cfpa/...                       CFPAOrg/Glossary 的原始 TSV
glossary/raw/i18n-dict-extender/Dict-Mini.json
glossary/index/glossary.db                  由 build 生成的只读索引
```

**上游地址、要同步的 12 个文件、更新流程和同步记录，全部写在 [`glossary-sources.md`](glossary-sources.md) 里**，本文件不再重复，以免两处走样。

两条红线：

> **不要自动更新。** 用户明确要求了才动。
>
> **刷新或重建前必须先向用户提交变更清单并获得确认**——术语库是全项目共用的地基，换一版数据会连带改变所有后续条目的校验结果。

> 词典数据遵循 CC BY-NC-SA 4.0（社区译文）与 Minecraft EULA（原版文本）。汉化产物应保留原作者与 CFPA 社区署名，且不得商用。
